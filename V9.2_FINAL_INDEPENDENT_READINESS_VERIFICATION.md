## 6. ACCOUNTS & TALLY VERIFICATION RESULTS

### **6.1 Architectural Protocol Verification: XML/HTTP vs ODBC**
- **Protocol:** TallyPrime 7.2 Integration uses the **HTTP XML / JSON API**, NOT ODBC.
- **Port:** Configured to port `9000` (Tally's default HTTP Server port).
- **Critical Technical Distinction:**
  - **ODBC (Port 9000 by default):** Uses binary wire protocol requiring a 64-bit Windows ODBC driver and DSN configuration.
  - **XML/HTTP (Port 9000 by default):** Operates via standard HTTP `POST` requests to `http://localhost:9000` sending XML envelopes (`<ENVELOPE><HEADER><TALLYREQUEST>Export Data</TALLYREQUEST>...</HEADER><BODY>...</BODY></ENVELOPE>`).
  - The ERP codebase uses HTTP POST requests (`fetch(endpoint, ...)`), which communicates directly with Tally's internal HTTP server.
  - **Audit Status:** **SIMULATED.** During this independent audit, no live TallyPrime instance was listening on port 9000. `checkTallyBridgeConnection` returned `connected: false, status: 'TALLY BRIDGE NOT CONNECTED'` as expected for offline execution.

### **7.2 Security Controls Assessment**
- **Supplier Cost & Margin Confidentiality:** Enforced across UI components (`QuotationFormWorkspace.tsx`, `PrintQuotationModal.tsx`), server actions (`quotations.ts`), and Customer 360 (`customer360.ts`). Non-authorized roles receive sanitized payloads with `purchase_price: 0` and `margin_pct: 0`.

- **HMAC Fail-Closed Audit Checkpoints:** Checkpoint verification requires a 32+ character `AUDIT_CHECKPOINT_HMAC_SECRET` in production. Falls closed with an operational error if missing. Never falls back to session secrets in production.
- **Gmail Token Security:** AES-256-GCM encryption with dynamic IV and authentication tag. Plaintext tokens are never stored, logged, or returned to client components.
