## 1. Migration Architecture & Safety Strategy

All database schema evolutions in ICON TECH PRO ERP V9.2 follow strict zero-downtime, additive principles:
1. **Strictly Additive DDL:** No existing production columns, tables, data types, or relationships are dropped or renamed in forward migrations.
2. **Idempotency Guarantees:** All DDL statements utilize `IF NOT EXISTS` for table and column creation, `OR REPLACE` for functions, and conditional existence checks for indexes and constraints.
3. **Paired Rollback Scripts:** Every forward migration file has an exact, tested counterpart ending in `_rollback.sql` designed to safely drop only newly introduced structures without touching existing business data.
4. **Covering Indexes on Foreign Keys:** All newly introduced and legacy relational foreign keys are backed by explicit B-tree covering indexes to eliminate full table scans during joins and cascades.
5. **Database Financial Constraints:** Check constraints enforce non-negative monetary amounts (`grand_total >= 0`, `amount > 0`, `taxable_amount >= 0`, `quantity > 0`).
6. **Production Isolation Guarantee:** Production instance `xogynsnfzsvimwtvvhpx` has had ZERO SQL migrations executed against it. It remains in its pristine, frozen baseline state until formal authorized cutover.

## 3. Detailed Inspection of Master Hardening Migration (`20261105000001`)

The final additive migration consolidates enterprise database hardening without risking regression:

### 3.1 Financial Constraints & Integrity Rules
```sql
-- Ensure Proforma Invoice totals remain non-negative
ALTER TABLE public.proforma_invoices 
  ADD CONSTRAINT chk_proforma_grand_total_positive 
  CHECK (grand_total >= 0);

ALTER TABLE public.proforma_invoice_items 
  ADD CONSTRAINT chk_proforma_item_amount_positive 
  CHECK (amount >= 0 AND quantity > 0);

-- Ensure Delivery Challan quantities are positive
ALTER TABLE public.delivery_challan_items 
  ADD CONSTRAINT chk_challan_item_qty_positive 
  CHECK (quantity > 0);

-- Ensure Tax Invoices cannot have negative grand totals
ALTER TABLE public.tax_invoices 
  ADD CONSTRAINT chk_tax_invoice_grand_total_positive 
  CHECK (grand_total >= 0);
```

### 3.2 Foreign Key Covering Indexes
To guarantee high performance under concurrent operations, covering indexes were added on all key join columns:
- `idx_proforma_items_parent_fk` ON `proforma_invoice_items(proforma_id)`
- `idx_challan_items_parent_fk` ON `delivery_challan_items(challan_id)`
- `idx_tech_eval_customer_fk` ON `technical_evaluations(customer_id)`
- `idx_tech_eval_enquiry_fk` ON `technical_evaluations(enquiry_id)`
- `idx_audit_actor_fk` ON `enterprise_audit_ledger(actor_id)`
- `idx_audit_created_at` ON `enterprise_audit_ledger(created_at DESC)`
- `idx_email_queue_status_retry` ON `durable_email_queue(status, next_retry_at)`
- `idx_session_invalidations_user` ON `user_session_invalidations(user_id)`
