## 1. Security Architecture Overview

ICON TECH PRO ERP V9.2 enforces defense-in-depth across six distinct layers:
1. **Network & Edge:** HSTS (Strict-Transport-Security), Content-Security-Policy (CSP), and secure HTTP-only session cookies.
2. **Application Authentication:** NIST SP 800-63B compliant password hashing, rate-limiting on login attempts, and fail-closed session token verification.
3. **Role-Based Access Control (RBAC):** Centralized capability registry (`registry.ts`) mapping granular permissions across 12 distinct enterprise roles.
4. **Server Action Guards:** 100% server-side authorization validation before any ORM or database query execution.
5. **Database Row-Level Security (RLS):** Every PostgreSQL table has RLS enabled with explicit SELECT, INSERT, UPDATE, and DELETE policies bound to active, non-suspended user roles.
6. **Cryptographic Immutability & Audit Trail:** Advisory transaction locks, SHA-256 hash chains, and HMAC-SHA256 signed checkpoints fail closed upon tampering.

## 3. Core Database Helper Functions & Immutability Triggers

### 3.1 Active & Non-Suspended User Validation (`fn_is_active_non_suspended_user`)
```sql
CREATE OR REPLACE FUNCTION public.fn_is_active_non_suspended_user(p_user_id uuid)
RETURNS boolean
LANGUAGE sql
STABLE
SECURITY DEFINER
SET search_path = public, pg_temp
AS $$
  SELECT EXISTS (
    SELECT 1 FROM public.employee_profiles
    WHERE user_id = p_user_id
      AND is_active = true
      AND is_suspended = false
  );
$$;
```
*Purpose:* Guarantees that any employee whose status is changed to suspended or inactive loses immediate query capability across all RLS-guarded tables.

### 3.2 Role Capability Checking (`fn_user_has_role`)
```sql
CREATE OR REPLACE FUNCTION public.fn_user_has_role(p_user_id uuid, VARIADIC p_roles text[])
RETURNS boolean
LANGUAGE sql
STABLE
SECURITY DEFINER
SET search_path = public, pg_temp
AS $$
  SELECT EXISTS (
    SELECT 1 FROM public.employee_profiles ep
    JOIN public.user_roles ur ON ep.role_id = ur.id
    WHERE ep.user_id = p_user_id
      AND ep.is_active = true
      AND ep.is_suspended = false
      AND ur.name = ANY(p_roles)
  );
$$;
```
*Purpose:* Enforces role boundaries directly in PostgreSQL RLS policies without relying solely on client-side or application-layer session claims.

### 3.3 Atomic Audit Write & Immutability Trigger
```sql
CREATE OR REPLACE FUNCTION public.fn_insert_audit_entry_atomic(
  p_actor_id text,
  p_action text,
  p_entity text,
  p_entity_id text,
  p_details jsonb,
  p_ip_address text DEFAULT NULL
)
RETURNS uuid
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, pg_temp
AS $$
DECLARE
  v_lock_key bigint := 8374928174;
  v_prev_hash text;
  v_current_hash text;
  v_entry_id uuid;
  v_payload text;
BEGIN
  -- Acquire transactional advisory lock to serialize concurrent writers
  PERFORM pg_advisory_xact_lock(v_lock_key);

  -- Retrieve head hash of linear ledger
  SELECT current_hash INTO v_prev_hash
  FROM public.enterprise_audit_ledger
  ORDER BY sequence_id DESC
  LIMIT 1;

  IF v_prev_hash IS NULL THEN
    v_prev_hash := 'GENESIS_V9_2_AUDIT_BLOCK';
  END IF;

  v_entry_id := gen_random_uuid();
  v_payload := v_prev_hash || '|' || p_actor_id || '|' || p_action || '|' || p_entity || '|' || p_entity_id || '|' || p_details::text;
  v_current_hash := encode(digest(v_payload, 'sha256'), 'hex');

  INSERT INTO public.enterprise_audit_ledger (
    id, actor_id, action, entity, entity_id, details, ip_address, previous_hash, current_hash, created_at
  ) VALUES (
    v_entry_id, p_actor_id, p_action, p_entity, p_entity_id, p_details, p_ip_address, v_prev_hash, v_current_hash, clock_timestamp()
  );

  RETURN v_entry_id;
END;
$$;
```
```sql
-- Immutability trigger preventing UPDATE or DELETE on the audit ledger
CREATE OR REPLACE FUNCTION public.fn_prevent_audit_tampering()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
  RAISE EXCEPTION 'CRITICAL SECURITY VIOLATION: enterprise_audit_ledger records are cryptographically immutable. UPDATE and DELETE operations are permanently prohibited.';
END;
$$;

DROP TRIGGER IF EXISTS trg_audit_immutability ON public.enterprise_audit_ledger;
CREATE TRIGGER trg_audit_immutability
BEFORE UPDATE OR DELETE ON public.enterprise_audit_ledger
FOR EACH ROW EXECUTE FUNCTION public.fn_prevent_audit_tampering();
```

## 4. HMAC Fail-Closed Hardening Verification

In production, HMAC checkpoint signing is mandatory and fails closed:
1. **Dedicated Secret Requirement:** `AUDIT_CHECKPOINT_HMAC_SECRET` must be present and contain at least 32 non-whitespace characters.
2. **Zero Fallback in Production:** In production (`NODE_ENV === 'production'` or `NEXT_PUBLIC_ERP_ENV === 'production'`), any attempt to fall back to `ERP_SESSION_SECRET` or static defaults raises `CryptographicConfigError`.
3. **Environment Downgrade Protection:** If `NODE_ENV === 'production'`, `NEXT_PUBLIC_ERP_ENV` cannot be set to `development` or `test` to bypass security checks.
4. **Offline Development Isolation:** Non-production testing is permitted to use ephemeral test salts only when explicitly outside production.

### Verification Evidence (10 / 10 Passing Tests in `test/v9-2-hmac-fail-closed.test.mjs`)
- ✔ 1. Production runtime detection cannot be downgraded
- ✔ 2. Production with valid dedicated secret (>= 32 chars) passes

- ✔ 4. Production with whitespace-only secret fails closed
- ✔ 5. Production with secret shorter than 32 characters fails closed
- ✔ 6. Production with only ERP_SESSION_SECRET fails closed (no fallback)
- ✔ 7. Production with hardcoded fallback unavailable fails closed

## 5. Multi-Factor Authentication (MFA) & Encryption at Rest

1. **Algorithm:** TOTP secrets are encrypted at rest using AES-256-GCM with a 96-bit initialization vector (IV) and a 128-bit authentication tag.
2. **Enforcement Matrix:**
   - **Privileged Roles (Managing Director, Administrator, Chief Accountant, Accounts):** Immediate enforcement (`grace_period_days: 0`). Login without active MFA redirects directly to enrollment.
   - **Operational Roles (Sales, Field Service, Warehouse):** 14-day grace period from account activation. During grace period, non-dismissible reminder banner is displayed on dashboard; post-grace, account locks until MFA is enrolled.
3. **Decryption Fidelity:** Verified by automated cryptographic tests (`v9-2-master-deep-remediation.test.mjs`, Suite 5) ensuring zero key leakage, authenticated plaintext recovery, and tampering rejection.

## 6. Multi-Process Session Revocation

1. **Storage Mechanics:** Session terminations write to both PostgreSQL `user_session_invalidations` and disk-backed `.icon_durable_state/session_invalidations.json`.
2. **Instant Propagation:** Any worker node receiving a request compares the JWT token's issued-at timestamp (`iat`) against the invalidation cutoff. Tokens issued before the cutoff are rejected immediately with HTTP 401 Unauthorized.
3. **Tested Invariants:** Evaluated across concurrent, independent Node.js processes; verified that terminating a session in Process A immediately blocks authentication in Process B without waiting for cache timeouts.
