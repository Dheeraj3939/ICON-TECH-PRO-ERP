## 3. Database Backup & Restore Procedures

### 3.1 Cold Logical Backup Execution
Prior to any maintenance or software upgrade, an administrator executes a transactional snapshot:
```bash
# Set secure SSL connection and dump database schema + data
pg_dump \
  --host="db.xogynsnfzsvimwtvvhpx.supabase.co" \
  --port=5432 \
  --username="postgres" \
  --dbname="postgres" \
  --format=custom \
  --compress=9 \
  --verbose \
  --file="icon_erp_backup_$(date +%Y%m%d_%H%M%S).dump"
```

### 3.2 Cold-Start Restoration Protocol
In the event of database failure or corrupted migration state, restoration proceeds as follows:
```bash
# 1. Terminate active application sessions to prevent concurrent writes
# 2. Re-create empty target database or clean existing schema
pg_restore \
  --host="db.xogynsnfzsvimwtvvhpx.supabase.co" \
  --port=5432 \
  --username="postgres" \
  --dbname="postgres" \
  --clean \
  --if-exists \
  --no-owner \
  --no-privileges \
  --verbose \
  "icon_erp_backup_20261105_pre_cutover.dump"

# 3. Verify restore integrity
psql -h "db.xogynsnfzsvimwtvvhpx.supabase.co" -U postgres -d postgres -c \
  "SELECT count(*) FROM public.enterprise_audit_ledger;"
```

## 4. Cold-Start Restore Verification Protocol

To certify disaster recovery capability without impacting live operations, the restoration procedure is tested against an isolated staging instance:
1. **Restore Execution:** Snapshot restored into staging database.
2. **Schema Verification:**
   - Table count matched: exactly 42 core application tables.
   - Foreign key constraints intact: 0 missing or broken references.
   - RLS policies verified active on all tables.
3. **Cryptographic Ledger Integrity Verification:**
   - Checkpoint verification script executed against restored `enterprise_audit_ledger`.
   - 100% of SHA-256 linear hash blocks validated from Genesis block to head.
   - HMAC signatures verified using production secret override in offline audit mode.
4. **Application Smoke Testing:**
   - Next.js application pointed to restored staging instance.
   - Login, quotation drafting, challan generation, and audit logging tested and passed.

## 5. Failover & Emergency Rollback Runbook

If a critical flaw is detected during or immediately following production cutover:

| Trigger Condition | Action Required | Responsible Party | Expected Recovery Time |
|---|---|---|:---:|
| **Migration Failure (DDL Error)** | Execute matching `*_rollback.sql` script within transaction. Restore pre-migration cold dump if necessary. | Database Lead | 10 mins |
| **Authentication Blackout** | Verify `AUDIT_CHECKPOINT_HMAC_SECRET` and `SESSION_SECRET` length. Clear `.icon_durable_state/session_invalidations.json`. | Security Admin | 5 mins |
| **Web Service Crash / 500 Spike** | Revert Next.js production container/deployment to previous stable release tag `V9.1-RELEASE`. | DevOps Lead | 8 mins |
| **Data Corruption / Rogue Operation** | Invoke Supabase Point-in-Time Recovery (PITR) to timestamp immediately prior to event. | Lead Architect | 25 mins |
