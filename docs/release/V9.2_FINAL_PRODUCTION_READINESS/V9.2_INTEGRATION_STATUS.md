## 2. Email Communication Infrastructure & Automated Failover

### 2.1 Dual-Provider Architecture
To ensure business continuity during network outages or vendor downtime, the email subsystem implements an active-passive failover pattern (`src/lib/email/providers/failover-provider.ts`):
1. **Primary Provider (Zoho Mail):**
   - Transmits formal quotations, proforma invoices, delivery challans, and customer notifications.
   - Operates through the organization's dedicated Zoho Mail accounts with direct SPF, DKIM, and DMARC alignment on `icontechpro.in`.
2. **Secondary Provider (Google Workspace / Gmail):**
   - Seamlessly assumes dispatch responsibility if Zoho returns an HTTP 5xx error, rate-limit rejection (429), or network timeout (> 8000ms).
   - OAuth 2.0 access and refresh tokens are encrypted at rest with AES-256-GCM (`gmail-crypto.ts`).
   - Scopes strictly confined to least-privilege permissions:
     - `https://www.googleapis.com/auth/gmail.send`
     - `https://www.googleapis.com/auth/gmail.readonly`

### 2.2 Durable Email Queue & Idempotency Guarantees
- **Queue Table:** `durable_email_queue`
- **Idempotency Key:** SHA-256 hash computed over `(recipient + subject + payload_checksum)`. Duplicate requests within a 24-hour window return the cached message ID with `duplicatePrevented: true` rather than transmitting duplicate emails.
- **Exponential Backoff:** Failed dispatches retry automatically at intervals: 1 min $\rightarrow$ 5 mins $\rightarrow$ 15 mins $\rightarrow$ 60 mins.
- **Dead-Letter Handling:** After 5 unsuccessful attempts, emails transition to `DEAD_LETTER` status, generating an executive notification banner on the Administrative Settings page.

## 3. WhatsApp Business Communication Subsystem

### 3.1 Architectural Principles
- **No Unofficial Puppeteer / Web Scrapers:** Unofficial WhatsApp Web automation libraries have been strictly avoided to eliminate the risk of IP bans, phone number blocking, or browser session crashes.
- **Official Click-to-Chat URI Scheme:** Quotations and delivery notifications generate authenticated deep links:
  $$\text{https://wa.me/91XXXXXXXXXX?text=ENCODED\_PAYLOAD}$$
- **Pre-Composed Summaries:** Automatically generates clean, professional quotation overviews:
  - Quotation Number & Date
  - Customer / Project Name
  - Total Items & Commercial Value (INR)
  - Secure Download Link / Document Reference
  - Assigned Sales Executive Contact

## 4. SMS & Telephony Gateway Architecture (TRAI DLT Ready)

### 4.1 Statutory Compliance Verification
In compliance with the Telecom Regulatory Authority of India (TRAI) Telecom Commercial Communications Customer Preference Regulations (TCCCPR, 2018):
- All outbound SMS dispatch functions (`src/lib/actions/communication.ts`) mandate:
  1. `EntityId`: 19-digit registered Principal Entity ID.
  2. `TemplateId`: Registered DLT Content Template ID.
  3. `SenderId`: 6-character approved alpha Header (e.g. `ICNPRG`).
- **Current Operational Status:** **DORMANT / READY**. The verification engine and payload formatting logic are active and tested (`test/v9-2-master-deep-remediation.test.mjs`, Suite 4). Gateway endpoint binding is deferred until corporate gateway credentials are submitted by procurement.
